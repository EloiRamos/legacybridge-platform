# Configuration

Configuration is environment variables (set by `compose.yaml`) plus secret files under `deploy/secrets/`
(git-ignored, generated by `make secrets`, mounted as Docker secrets). The names below are the ones the application
reads. Every active line of `.env.example` is consumed by `compose.yaml` (checked by
`backend/tests/security/test_env_contract.py`); variables compose does not pass are commented out there.

## Application (`app` service)

| Variable | Default | Notes |
|---|---|---|
| `LBF_PROFILE` | `default` | `demo`, `test` |
| `LBF_PUBLIC_ORIGIN` | `http://127.0.0.1:8080` | Origin required on state-changing requests; passed through by compose |
| `LBF_COOKIE_SECURE` | `false` | passed through by compose; must be `true` behind TLS (TLS is not part of this deployment) |
| `LBF_DB_HOST`, `LBF_DB_NAME`, `LBF_DB_PORT` | `db`, `lbf`, `5432` | passwords from `db_app` / `db_audit_reader` secret files |
| `LBF_HALDEN_URL` | `http://halden:8090` | `test`: `http://wiretap:8090` |
| `LBF_HALDEN_LOGIN` | `svc_bridge` | HALDEN's single service login |
| `LBF_HALDEN_SECRET_FILE` | `/run/secrets/halden_secret` | Docker secret `halden_secret`, also mounted into `halden`; no environment value or default |
| `LBF_TRANSPORT_TIMEOUT_SEC` | `5` | HALDEN client timeout; `test`: `1` |
| `LBF_SKARVIK_EXCHANGE_DIR` | `/exchange` | the shared volume `lbf-skarvik-exchange` |
| `LBF_SKARVIK_CONTROL_URL` | `http://skarvik:8095` | used only by the demo router |
| `LBF_TIME_SCALE`, `LBF_TEST_PAUSE_POINTS` | `1.0`, empty | honoured only in the `test` profile |
| `LBF_SIM_CONTROL` (compose) | `false` | enables the simulators' control planes (`demo`/`test` only) |

## Assistant (optional, off by default)

| Variable | Default | Notes |
|---|---|---|
| `LBF_ASSISTANT_PROVIDER` | `disabled` | `disabled` (guided router, no model), `scripted` (tests), `openai` |
| `LBF_LIVE_INFERENCE` | `false` | compose pins it to `false`; live calls need **both** `openai` and `true` |
| `OPENAI_MODEL` | `gpt-6-luna` for `openai`, otherwise unset | the only accepted value; any other is `CONFIG_REJECTED` (no client, no request). It enables nothing by itself. Evaluation, live-validation and smoke runs still need it set explicitly, and an authorization that names it ([ADR-F10](../adr/ADR-F10-openai-provider.md)) |
| `OPENAI_API_KEY_FILE` | `/run/secrets/openai_api_key` | the owner places the key in `deploy/secrets/openai_api_key.txt`; mounted only into `app` |
| `LBF_OPENAI_INPUT_PRICE_PER_MTOK`, `LBF_OPENAI_CACHED_INPUT_PRICE_PER_MTOK`, `LBF_OPENAI_OUTPUT_PRICE_PER_MTOK`, `LBF_OPENAI_PRICE_SOURCE`, `LBF_OPENAI_PRICE_OBSERVED_AT` | unset | all required for `openai` (fail closed otherwise); enter prices with their source and date |
| `LBF_OPENAI_TIMEOUT_SEC`, `LBF_OPENAI_MAX_OUTPUT_TOKENS`, `LBF_OPENAI_MAX_RETRIES`, `LBF_OPENAI_RETRY_MAX_WAIT_SEC`, `LBF_OPENAI_MAX_CONCURRENCY`, `LBF_OPENAI_MAX_REQUESTS_PER_TURN` | see `backend/src/lbf/assistant/config.py` | bounded explicit retries; SDK retries are always 0 |
| `LBF_OPENAI_MAX_REQUEST_COST_USD`, `LBF_OPENAI_MAX_TURN_COST_USD`, `LBF_OPENAI_DAILY_BUDGET_USD` | see config | reservation before each request; exhausted budget ⇒ deterministic router with a notice |

Costs are **estimates** computed from the configured prices and the tokens the provider reports; the provider's
dashboard and invoice are authoritative. Enabling live inference **in the `app` service** changes `compose.yaml`'s
pinned `false` and is an owner decision ([ADR-F10](../adr/ADR-F10-openai-provider.md)); the host-run
live runs on record are listed in [KNOWN_LIMITATIONS](../KNOWN_LIMITATIONS.md) (L-02).

### Live smoke (host process, not Compose)

The optional live smoke (`make openai-smoke`) runs on the host and reads the variables above from its own shell; it
does not change `compose.yaml`. It additionally uses:

| Variable | Default | Notes |
|---|---|---|
| `LBF_EVAL_AUTHORIZATION` | `governance/eval/AUTHORIZATION.json`, **relative to the working directory** | `make openai-smoke` runs in `backend/`, so always set the absolute path `<repo>/governance/eval/AUTHORIZATION.json` (the `backend/governance/` location is not git-ignored) |
| `LBF_O1A_EXECUTE` | unset | must equal the authorization's `run_id`; unset ⇒ validated but not executed |
| `OPENAI_API_KEY_FILE` | `/run/secrets/openai_api_key` | container path; on the host set `<repo>/deploy/secrets/openai_api_key.txt` and leave `OPENAI_API_KEY` unset |

For the smoke, `LBF_OPENAI_MAX_RETRIES` is forced to `0` and `LBF_OPENAI_MAX_REQUESTS_PER_TURN` to `2`; the turn and
daily budgets do not apply (all requests use the evaluation budget `max_estimated_usd`). Prices, price source and
date must equal the authorization; `LBF_OPENAI_MAX_OUTPUT_TOKENS`, `LBF_OPENAI_MAX_REQUEST_COST_USD` (a zero value
falls back to 0.20) and `LBF_OPENAI_MAX_CONCURRENCY` must not exceed it. Reasoning effort is not configurable. The
request cap is held in the durable ledger `governance/eval/smoke-ledger/` (initialized once with
`python -m lbf.assistant.smoke init-ledger`; never deleted). The smoke is run by the
owner of the API key.

## Secrets and rotation

| File | Rotation |
|---|---|
| `db_superuser.txt`, `db_migrator.txt`, `db_app.txt`, `db_audit_reader.txt` | change the role password in PostgreSQL (`ALTER ROLE … PASSWORD`), update the file, `make up` to restart `app` |
| `openai_api_key.txt` | replace or empty the file and restart `app`; revoke the old key at the provider |
| `demo-credentials.txt` | demo personas only; change passwords through the admin role or recreate the database |
| `halden_secret.txt` | replace the file (e.g. 48 random hex characters) and `docker compose up -d --force-recreate halden app`; both sides read the same Docker secret. The `test` profile mounts the public fictional fixture `deploy/test-fixtures/halden_secret.txt` instead (L-04) |

## Fixed policy values (code, not configuration)

Step-up 15 min · session idle 30 min, absolute 8 h · lockout 15 min after 5 failed logins · login limit 10/min per
address · validation snapshot valid 10 min · value threshold €2,500 for `approval.grant.any` · re-check at most once per
10 s per operation · SKARVIK ack deadline 300 s, dedup window 72 h with 1 h safety margin (test profile: 20 s, 120 s,
10 s).
